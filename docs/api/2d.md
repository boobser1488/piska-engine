# 2D: листы спрайтов, анимация, частицы, тайлмапы

Всё из этого файла есть в `engine::prelude::*` (типы) и регистрируется в
`engine::app()` — значит, сохраняется в сценах и редактируется в инспекторе.
Рабочий пример: `cargo run --example features2d`
(`crates/engine/examples/features2d.rs`), тесты — `crates/engine/tests/features2d.rs`.

Общее:

* Мир 2D лежит в плоскости XY, Y вверх. Камера — `Camera::orthographic(половина_высоты)`.
* Порядок рисования: `sorting_layer` → `order` → глубина (Z). Больше — поверх.
  Спрайты, частицы, тайлмапы и следы сортируются **вместе** по этой паре.
* Диапазоны в частицах — `Vec2(min, max)`: значение берётся случайно между ними.
* Для пиксель-арта поставьте в `.meta` текстуры `"filter": Enum("Nearest")`.

## 1. Листы спрайтов (`SpriteRenderer`)

Новые поля (старые сцены загружаются как раньше — у полей есть значения по умолчанию):

| поле | по умолчанию | смысл |
|---|---|---|
| `flip_x`, `flip_y` | `false` | отражение по осям |
| `pivot: Vec2` | `(0.5, 0.5)` | точка опоры в долях спрайта; `(0.5, 0.0)` — «ноги» |
| `uv_offset`, `uv_size: Vec2` | `(0,0)`, `(1,1)` | прямоугольник-источник в долях текстуры, от левого верхнего угла |
| `sheet_columns`, `sheet_rows: u32` | `1`, `1` | сетка кадров внутри источника |
| `frame: u32` | `0` | номер кадра: слева направо, сверху вниз, с нуля |

```rust
let sheet: AssetHandle<Texture> = assets.handle("sprites/hero_sheet.png")?;
app.spawn("Hero")
    .with(SpriteRenderer::sheet(sheet, 6, 3).with_size(1.6, 1.6).with_pivot(0.5, 0.0));

// Произвольный кусок картинки (в пикселях; нужны размеры текстуры):
let atlas = SpriteRenderer::textured(tex).with_source_pixels(32.0, 0.0, 16.0, 16.0, 128.0, 64.0);
```

Конструкторы: `SpriteRenderer::sheet(texture, columns, rows)`, `.with_frame(i)`,
`.with_pivot(x, y)`, `.with_source_pixels(x, y, w, h, tex_w, tex_h)`, `.frame_count()`.
При линейной фильтрации кадр сдвигается внутрь на полтекселя (соседний кадр не просвечивает);
у `Nearest` сдвига нет. Вдали (уменьшенная копия текстуры, мипмап) шейдер дополнительно
держит выборку внутри кадра на полтекселя выбранного мипа — между плитками карты и кадрами
листа не проступают соседние кадры ни при дробных сдвигах камеры, ни при отдалении
(проверка — `crates/engine/tests/atlas_seams.rs`).

## 2. Анимация (`SpriteAnimator`)

Вешается на объект со `SpriteRenderer` и каждый кадр пишет в него `frame`.
Клипы — строки `"имя: кадры @fps режим"` (удобно править в сцене и инспекторе):

```text
"idle: 0-3 @5"              кадры 0…3, 5 кадров/с, по кругу (режим loop по умолчанию)
"jump: 14,15,16 @10 once"   один проход и остановка
"wave: 0-4 @8 pingpong"     туда и обратно
"back: 3-1"                 диапазон можно писать в обратную сторону
```

```rust
let animator = SpriteAnimator::new()
    .with_clip("idle: 0-3 @5")
    .with_clip("run: 6-11 @13")
    .with_clip("hit: 15-17 @12 once")
    .starting_with("idle");
app.spawn("Hero").with(SpriteRenderer::sheet(sheet, 6, 3)).with(animator);

// В скрипте:
if let Some(anim) = ctx.get_mut::<SpriteAnimator>() {
    anim.play(if running { "run" } else { "idle" }); // можно звать каждый кадр
    // anim.restart("hit");   // всегда с первого кадра
    // anim.speed = 2.0;      // поле reflection: множитель скорости
}
```

* `play(name)` — ничего не делает, если клип уже играет; `restart(name)` — всегда с начала.
  Неизвестное имя игнорируется (одно предупреждение в лог).
* Состояние: `current_clip()`, `current_frame()`, `is_finished()`, поля `playing`, `speed`, `time`.
* Когда `once`-клип дошёл до конца: компонентам этого же объекта приходит сообщение
  `ANIMATION_FINISHED` (`"animation_finished"`, значение `Value::Str(имя клипа)`) в `on_message`,
  а в `world.events` лежит `AnimationFinished { object, clip }`
  (`world.events.read::<AnimationFinished>()`).
* Ошибки в строке клипа (нет двоеточия, плохой диапазон…) пишутся в лог один раз с подсказкой,
  клип пропускается. Разобрать вручную: `AnimationClip::parse("run: 0-3 @8")`.

Анимация идёт в игре (в `on_update`); в редакторе при остановленной игре кадр не листается.

## 3. Частицы (`ParticleSystem`)

CPU-симуляция, рисуются билбордами (всегда лицом к камере) в **одном** draw call на систему,
без аллокаций на частицу. Работают в 2D-сцене и в 3D.

Одной строкой, готовые эффекты (все зацикленные, кроме помеченных «разово»):

```rust
app.spawn("Boom").at(3.0, 0.0).with(ParticleSystem::explosion());   // разово, удаляет объект сам
app.spawn("Dust").at(x, y).with(ParticleSystem::dust());           // разово, удаляет объект сам
app.spawn("Pick").at(x, y).with(ParticleSystem::pickup_sparkle()); // разово, удаляет объект сам
app.spawn("Sparks").at(x, y).with(ParticleSystem::sparks());       // искры-штрихи с гравитацией
app.spawn("Smoke").at(x, y).with(ParticleSystem::smoke());
app.spawn("Fire").at(x, y).with(ParticleSystem::fire());
```

Из скрипта (объект создаётся и сам исчезает):
`ctx.world.scene.build("Boom").at(x, y).with(ParticleSystem::explosion()).id();`

Подстройка: `.scaled(0.5)` (размеры, скорости, гравитация), `.in_3d()` (летят во все стороны,
а не в плоскости XY; пресеты по умолчанию плоские), `.with_seed(n)`, `.with_layer(sorting_layer, order)`,
`.with_texture(handle)`. Любое поле можно переопределить обычным
`ParticleSystem { emission_rate: 30.0, ..ParticleSystem::sparks() }`.

Поля:

| поле | смысл |
|---|---|
| `playing`, `duration`, `looping`, `destroy_when_done` | цикл эмиссии: `looping: false` — один проход за `duration`; `destroy_when_done` — когда эмиссия кончилась и частиц нет, объект удаляется |
| `emission_rate` | частиц в секунду |
| `bursts: Vec<Vec2>` | залпы: `(время от начала цикла, число частиц)` |
| `max_particles` | потолок живых частиц |
| `lifetime`, `start_speed`, `start_size`, `start_rotation` (градусы), `rotation_speed` (град/с) | диапазоны `(min, max)` |
| `start_color`, `start_color_max` | каждая частица — случайная точка между двумя цветами; компоненты > 1 светятся через блум |
| `gravity: Vec3`, `drag` | ускорение в мировых координатах; сопротивление |
| `color_over_lifetime: Vec<Color>` | множитель цвета: ключи равномерно от рождения до смерти (2–3 ключа — градиент); пусто — без изменений. По умолчанию — белый → прозрачный |
| `size_over_lifetime: Vec<f32>` | множитель размера, ключи равномерно |
| `shape`, `shape_size`, `cone_angle` | `Point` — из точки; `Circle` — из диска радиуса `shape_size.x` наружу; `Sphere` — из шара наружу (при `flat` — диск); `Cone` — веером вокруг оси +Y объекта, полуугол `cone_angle`; `Box` — из прямоугольника `shape_size`. Направление «вверх» — локальная ось Y объекта, так что объект можно повернуть |
| `flat` | только плоскость XY (для 2D) |
| `space` | `World` — частицы остаются на месте, когда эмиттер едет; `Local` — едут вместе с ним |
| `blend` | `Alpha` или `Additive` (сложение света; в HDR-сцене с `Environment.bloom` частицы светятся) |
| `texture`, `particle_shape` | текстура; без неё `Soft` (мягкое пятно), `Circle` (круг), `Square` |
| `sheet_columns`, `sheet_rows`, `sheet_over_lifetime` | лист спрайтов: случайный кадр на частицу или листание по жизни |
| `velocity_stretch` | вытягивание вдоль скорости (штрихи искр): добавка длины = скорость × значение |
| `sorting_layer`, `order` | как у спрайтов |
| `seed` | зерно ГСЧ: одинаковое зерно — одинаковое поведение (тесты); 0 — каждый раз по-разному |

Управление из кода (на компоненте): `burst(n)` — выпустить n частиц сразу, `stop()` — прекратить
эмиссию (живые доживают), `restart()`, `clear()`, `alive_count()`, `particles()` (чтение),
`is_emitting()`, `is_finished()`. Шаг симуляции вручную (для тестов): `simulate(dt, world_matrix)`.

Замечания: симуляция идёт в игре (`on_update`), `dt` кадра ограничен 0.1 с; частицы одной системы
рисуются от старых к новым и не сортируются по глубине (в 3D с `Alpha` для густых облаков берите
`Additive` или небольшие системы).

## 4. Карты тайлов (`Tilemap`)

Сетка индексов поверх тайлсета (картинка с сеткой одинаковых ячеек). Объект стоит в
**левом нижнем углу** карты. Рисуется одним заходом; в кадр попадают только видимые тайлы
(карта 200×200 стоит как 4×4 на экране).

Запись карты — поле `rows`, по строке на ряд, **сверху вниз**, тайлы в строке через пробел:

```ron
(kind: "Tilemap", fields: {
    "tileset": Asset("…guid…"),
    "tileset_columns": Int(4),
    "tileset_rows": Int(2),
    "tile_size": Vec2(1.0, 1.0),
    "rows": List([
        Str("24*."),
        Str("5*. 4 4 4 15*."),
        Str("24*1"),
        Str("24*2"),
    ]),
    "collision": Enum("NonEmpty"),
    "one_way_tiles": List([Int(4)]),
}),
```

* `.` (а также `0`, `-`, `_`) — пусто; `n` — ячейка `n − 1` тайлсета (слева направо, сверху вниз,
  как в Tiled); `12*3` — «двенадцать тайлов 3 подряд». Короткие строки добиваются пустыми.
* Нераспознанные слова не роняют игру: ячейка пустая, одно предупреждение в лог
  (`tilemap.problems()` — список).

```rust
let map = Tilemap::from_rows(&[
        "8*.",
        ". . 4 4 4 . . .",
        "8*1",
    ])
    .with_tileset(tileset, 4, 2)   // столбцов × строк в картинке
    .with_tile_size(1.0, 1.0)      // мировые единицы на тайл
    .with_layer(0, 0)              // sorting_layer, order
    .with_solid_nonempty()         // все непустые тайлы — стены
    .with_one_way_tiles(&[4]);     // …кроме «облачков»
app.spawn("Ground").at(-4.0, -3.0).with(map);
```

Несколько карт друг над другом — разные `sorting_layer` (фон −5, земля 0, передний план 4;
герой между ними, например 2).

Из кода: `size()`, `tile(x, y)`, `set_tile(x, y, n)` (`y` — строка сверху; карта растёт при
выходе за край, коллайдеры пересобираются сами), `cell_at(локальная_точка) -> Option<(x, y)>`,
`cell_center(x, y)`, `grid()` (разобранная сетка), `solid_rects()`, `one_way_rects()`.

### Коллизии

`collision`: `None` (по умолчанию), `NonEmpty` (все непустые тайлы твёрдые) или `Listed`
(только индексы из `solid_tiles`). `one_way_tiles` — индексы тайлов-«облачков»: сверху держат,
снизу и сбоку пропускают (локальная ось Y карты). `collider_friction`, `collider_layer`
(слой `GameObject::layer` создаваемых объектов, влияет на `collides_with` других коллайдеров).

Твёрдые тайлы жадно сливаются в минимум прямоугольников (горизонтальные отрезки, затем
одинаковые по ширине склеиваются вниз): пол 24 тайла — один коллайдер. Для каждого прямоугольника
`Tilemap` создаёт дочерний объект `TileCollider` со статическим `Collider2D` (дети переживают
поворот и масштаб карты). Правка `rows` / настроек во время игры пересобирает набор.

Как устроена связка: `engine-physics` не зависит от `engine-render`, поэтому тайлмап не ссылается
на тип `Collider2D`, а создаёт его по имени через `world.registry` и `set_field` (reflection).
Если `Collider2D` не зарегистрирован — одна понятная ошибка в лог, игра продолжается без коллайдеров.
Детей `TileCollider`, сохранённых в сцене, при старте карта удаляет и строит заново.

## 5. Следы (`TrailRenderer`)

Лента за движущимся объектом: точки пути живут `lifetime` секунд, ширина и цвет меняются
от головы к хвосту.

```rust
app.spawn("Comet").with(TrailRenderer::glowing(Color::rgb(0.9, 2.2, 3.0), 0.35, 0.9));
```

Поля: `lifetime`, `start_width`, `end_width`, `start_color`, `end_color`, `min_vertex_distance`,
`max_points`, `emitting`, `blend` (`Alpha` / `Additive`), `sorting_layer`, `order`.

## 6. Камера 2D (`CameraController2D`)

Вешается на объект с `Camera`: следит за объектом по тегу, сглаживает, ограничивает центр
прямоугольником и трясёт.

```rust
app.spawn("Camera").tag("MainCamera")
    .with(Camera::orthographic(5.0))
    .with(CameraController2D::following("Player")
        .with_offset(0.0, 1.5)
        .with_smoothing(6.0)
        .with_bounds(Vec2::new(-3.0, 0.0), Vec2::new(3.0, 0.0)));

// Тряска: травма 0..1, затухает сама; сдвиг пропорционален квадрату травмы.
ctx.send_message(camera_id, SHAKE_MESSAGE /* "shake" */, Value::Float(0.4));
// или напрямую: ctx.scene_mut().get_component_mut::<CameraController2D>(camera_id)?.add_shake(0.4);
```

Поля: `target_tag`, `offset`, `smoothing` (1/с; 0 — прилипает), `dead_zone`, `use_bounds`,
`bounds_min`, `bounds_max`, `trauma`, `shake_decay`, `shake_max_offset`, `shake_frequency`.
Первый кадр камера ставится на цель сразу, без «подъезда».
Границы относятся к **центру** камеры: вычтите половину видимой области сами.

## Производительность и ограничения

* Спрайты, частицы, тайлы и ленты собираются в один буфер вершин, сортируются по
  `(sorting_layer, order, глубина)` и склеиваются в батчи по `(текстура, смешивание)`;
  буферы переиспользуются между кадрами. Draw call — на смену текстуры или режима смешивания.
* Сильный совет: игровые тайлсеты, листы и частицы держите на одной текстуре на слой — так
  батчей меньше.
* Анимация, частицы и слежение работают только в игре; в редакторе при остановленной игре
  частицы не симулируются.
* Нет: тайлы с анимацией и отражением отдельного тайла, изометрия/гекс-сетки, слои внутри одной
  карты (используйте несколько карт), мягкие частицы с глубиной.

## Свой шейдер спрайта

Компонент `SpriteShader { shader, params }` рядом со `SpriteRenderer` рисует спрайт своей
функцией (`//! kind: sprite`): обводка, вспышка, смена палитры. Спрайты с одним шейдером и
одинаковыми значениями — одна пачка. Эффекты на весь экран — `PostEffect` на камере.
Подробно — `docs/api/shaders.md`.
