# Рельеф и вода (`Terrain`, `Water`)

Большая земля как в проекте-образце: процедурный рельеф из слоёв шума (материки и море,
холмы, горные хребты, выровненные площадки) или карта высот, разбитый на чанки с
уровнями детализации, подгружаемый вокруг камеры, с текстурами по высоте и уклону,
раскраской и скульптом кистью, тенями, туманом, водой и коллайдером для 3D-физики.
Всё нужное — в `engine::prelude::*`.

## Быстрый старт

```rust
use engine::prelude::*;

fn main() -> Result<(), EngineError> {
    let mut app = engine::app();
    // Рельеф 2 × 2 км, центр — в начале координат (позиция объекта — угол рельефа).
    app.spawn("Terrain")
        .at3(-1024.0, 0.0, -1024.0)
        .with(Terrain { seed: 99, size: 2048.0, ..Terrain::default() });
    app.spawn("Sea").with(Water::default()); // море на высоте 0 до горизонта
    app.spawn("Sun")
        .rotation(Quat::from_euler(EulerRot::YXZ, -0.5, -0.7, 0.0))
        .with(Light::default());
    app.spawn("Camera")
        .at3(-260.0, 95.0, 420.0)
        .with(Camera { far: 4000.0, ..Camera::perspective(60.0) });
    engine::run(app, WindowConfig::titled("Terrain"))
}
```

Камере нужен дальний план под дальность прорисовки (`far`, по умолчанию 1000 м), а туман
(`Environment::fog_density`, например 0.0005) растворяет край видимой земли в небе.

## Где лежит рельеф

* Позиция объекта — **угол** рельефа (x, z) и **нулевая высота** (y). Рельеф уходит в +x и
  +z на `size` метров. Поворот и масштаб объекта не применяются (как в Unity).
* `size` округляется до целого числа чанков (`chunk_size`, по умолчанию 64 м), до 256
  чанков на сторону. `Terrain::extent()` — сторона после округления, `layout()` — число
  чанков, клеток и шаг сетки.
* Сетка отсчётов: `resolution` клеток на сторону чанка в ближнем LOD (16, 32, 64 или
  128; по умолчанию 64 — шаг 1 м). Между отсчётами — два треугольника; так же режут
  клетки меш, коллайдер и `terrain_height`, поэтому всё совпадает.

## Параметры формы

| Поле | По умолчанию | Что делает |
|---|---|---|
| `source` | `Procedural` | `Procedural` — шум, `Heightmap` — картинка `heightmap` |
| `seed` | 1337 | Сид: один сид — один рельеф (на любой машине и в любом потоке) |
| `size` | 1024 | Сторона, м |
| `chunk_size`, `resolution` | 64, 64 | Сторона чанка (м) и клеток на сторону |
| `noise_scale` | 1 | 2 — все формы вдвое шире (как в образце при 1) |
| `height_scale` | 1 | Множитель всех высот (0 — плоско) |
| `mountains` | 1 | Высота горных хребтов (0 — без гор) |
| `octaves` | 5 | Октавы холмов (у хребтов на одну больше) |
| `land_bias` | 0.18 | Суша против моря: больше — больше суши |
| `flat_zones` | — | Площадки `Vec3(x, z, радиус)` от угла рельефа: земля выровнена (под города, карты) |
| `flat_falloff` | 40 | Ширина перехода от площадки к природному рельефу, м |

Генератор — перенос генератора образца: искажённая область (warp), материки
(уровень моря — 0, дно до −38 м), холмы ниже у побережья, гребенчатые хребты до ~380 м
только вглубь суши под маской, мелкие неровности. Площадка ровная на высоте природной
земли в её центре (не ниже +2 м). Сиды для пробы на 2 км: 99 — побережье, озёра и горы;
123 — сплошные горы; 1337 — низины и берег.

## Карта высот

```rust
let heightmap = assets.handle::<Texture>("terrain/island.png")?; // 16-битный PNG
app.spawn("Island").with(Terrain {
    source: TerrainSource::Heightmap,
    heightmap,
    heightmap_height: 300.0, // белый = 300 м, чёрный = 0
    size: 1024.0,
    ..Terrain::default()
});
```

Картинка растягивается на весь рельеф (билинейно), верхняя строка — край z = 0.
Читаются PNG (лучше 16-битный серый — 8 бит дают «ступеньки»), а также квадратные
`.raw` / `.r16` (little-endian u16), если такой файл есть в базе ассетов. Разнообразие
текстур (пятна, линия снега) и тут берётся из шума по `seed`. Без базы ассетов (скрипт
спросил высоту до первого кадра) карта считается плоской.

## Чанки, LOD и подгрузка

Как в образце:

* Пять уровней детализации: ближний — `resolution` клеток на чанк, каждый следующий
  вдвое реже (до 4 × 4). Уровень выбирается по расстоянию от камеры до чанка:
  < 2, 5, 10, 20 чанков и дальше; `lod_distance` умножает эти пороги (2 — детальнее
  вдали, но больше треугольников).
* Щели между чанками разного уровня закрыты дважды: край чанка, за которым сосед
  грубее, «пришивается» к его краю (точное совпадение — этого в образце нет), а «юбки»
  (полосы вниз по краям, как в образце) закрывают остаток, пока сосед перестраивается.
* Чанки строятся в фоновых потоках (до трёх; в браузере — по 3 мс за кадр в основном
  потоке), на GPU копируется не больше 16 готовых чанков за кадр — без рывков при
  полёте. Пока камера стоит и ничего не меняется, поиск недостающего не идёт.
* Чанки дальше `view_distance` (по умолчанию 1500 м) + один чанк выгружаются. Если один
  рендерер рисует несколько видов (Scene и Game в редакторе), подгрузка учитывает все
  камеры последних кадров: уровень — самый детальный из нужных, выгрузка — только вдали
  от всех.
* На остром гребне центральная разность даёт «плоскую» нормаль; материал выбирается по
  самому крутому одностороннему уклону вершины, поэтому гребни не покрываются песком.
  Невидимые отсекаются по пирамиде камеры; в карту теней идут чанки ближе
  `Environment::shadow_distance`.
* Вершина — 24 байта, индексы 16-битные и общие для всех чанков уровня, чанки уровня
  лежат слотами в общих буферах по 4 МБ.

Рендерер без окна (`Renderer::headless`, `ENGINE_SCREENSHOT`) и снимки редактора строят
всё нужное сразу, в том же кадре. Своему рендереру: `renderer.set_terrain_blocking(true)`.
Статистика кадра: `renderer.terrain_stats()` — `TerrainStats { chunks_loaded,
chunks_drawn, triangles, draw_calls, shadow_chunks, uploads, pending, gpu_bytes,
lod_counts, build_ms, .. }`.

## Текстуры и слои

Пять слоёв — трава, земля, скала, песок, снег (`TERRAIN_LAYERS`) — смешиваются сами,
как в образце:

* трава — основа; земля — на уклонах и пятнами; песок — у моря (`sea_level`); скала — на
  крутых склонах и высоко (трипланарно: на обрывах без растяжения); снег — выше
  `snow_height` (по умолчанию 200 м) на не слишком крутом;
* `desert` = 1 — пустыня: песок вместо травы, тёплые скалы и земля, без снега;
* смешивание «по высоте текселя»: на границе побеждает более высокий тексель — края
  естественные, а не размытые; вблизи — деталь (mod2x), крупный оттенок против повторов;
* свет — как у мешей: солнце (GGX) с тенями, точечные источники, ambient неба,
  туман; запечённое затенение впадин (AO).

Встроенные текстуры генерируются кодом при первом рельефе (`terrain_textures.rs`, файлов
нет). Свои: `grass_texture` … `snow_texture` — любая картинка (приводится к 256 × 256,
высота для смешивания и нормаль — по яркости). Оттенки `grass_color` … `snow_color`
умножаются на текстуру. `texture_scale` = 2 — узор вдвое крупнее.

**Раскраска** кистью (`BrushTool::Paint`) рисует веса слоёв поверх автоматических;
«стереть» (`layer: None`) возвращает автоматические слои. Разрешение раскраски — сетка
отсчётов (1 м при настройках по умолчанию).

## Вода

```rust
app.spawn("Sea").at3(0.0, 0.0, 0.0).with(Water::default());           // до горизонта
app.spawn("Pond").at3(40.0, 12.0, -30.0).with(Water { size: 60.0, ..Water::default() });
```

Плоскость на высоте объекта; `size` 0 — квадрат следует за камерой (море образца), иначе —
квадрат `size` с центром в позиции объекта. Волны — только в освещении (нормаль),
отражение неба по Френелю, блик солнца, туман. `deep_color`, `opacity`, `waves`,
`wave_speed`. Вода прозрачная и глубину не пишет; рисуется после всего непрозрачного.

## Физика и запросы из скриптов

Коллайдер создаётся сам (`engine::app()` подключает подсистему
`engine::terrain_physics::TerrainPhysicsSystem`): по `HeightField` Rapier на чанк, с
высотами ближнего LOD. Под динамическими телами и персонажами (`CharacterController`) и
вокруг них плитки появляются сразу, перед шагом физики; остальные — в фоне (1,5 мс за
шаг), пока не покрыт весь рельеф. `Physics3D::raycast` возвращает объект рельефа.
Изменённые скульптом чанки перестраиваются. Трение — 0.8, слой — `GameObject::layer`.

```rust
impl Component for Dropper {
    fn on_update(&mut self, ctx: &mut Ctx, _dt: f32) {
        let p = ctx.world_position();
        // Unity: Terrain.SampleHeight. None — под точкой нет рельефа.
        if let Some(ground) = terrain_height(ctx.world, p.x, p.z) {
            let normal = terrain_normal(ctx.world, p.x, p.z).unwrap_or(Vec3::Y);
            ctx.transform().position.y = ground; // стоять на земле
            let _slope_deg = normal.y.acos().to_degrees();
        }
        // Луч по рельефу без физики (работает и в редакторе):
        if let Some(hit) = terrain_raycast(ctx.world, p + Vec3::Y * 100.0, Vec3::NEG_Y, 500.0) {
            log::info!("ground at {} on {:?}", hit.point, hit.object);
        }
    }
}
```

`snap_to_terrain(world, id, offset)` ставит объект на землю под ним (+ `offset`).
Для многих запросов к одному рельефу — `terrain.sampler(assets)`: `height_local(x, z)`,
`normal_local`, `raycast_local` в локальных координатах (от угла рельефа).
Плиткам-коллайдерам из своего кода: `Physics3D::set_heightfield_tile(owner, (cx, cz),
HeightfieldTile { .. })`, `remove_heightfields(owner)`.

Из C++ (сервисы фасада, см. `cpp.md` §13):

```cpp
auto r = engine::call_service("terrain.height", {x, z}, 1);   // пусто — под точкой нет рельефа
if (!r.empty()) { float ground = r[0].to_float(); }
auto n = engine::call_service("terrain.normal", {x, z}, 1);   // [Vec3]
```

## Скульпт и раскраска из кода

```rust
let mut terrain = Terrain::default();
// Кисть: Raise, Lower, Smooth, Flatten (к target_height), Paint (слой layer).
let brush = TerrainBrush { tool: BrushTool::Raise, radius: 12.0, strength: 0.5, falloff: 0.6, ..TerrainBrush::default() };
terrain.apply_brush(&brush, 300.0, 280.0, 1.0 / 60.0, None); // центр — локальные x, z; dt — секунды
// Unity: TerrainData.SetHeights — высоты в прямоугольнике по функции:
terrain.modify_heights(Vec2::new(100.0, 100.0), Vec2::new(140.0, 140.0), None, |_p, h| h.max(20.0));
terrain.clear_edits(); // убрать весь скульпт и раскраску
```

Меняются только отсчёты внутри кисти / прямоугольника; рендер перестраивает только
затронутые чанки, физика — только их коллайдеры.

## Как хранятся правки

Скульпт и раскраска — правка поверх базы (шума или карты высот) в поле `edits`
(`TerrainEdits`). В файле сцены это одна строка внутри компонента (отдельного файла рядом
со сценой нет — сцена переносится и копируется целиком, Undo работает как с любым полем):
плитки 64 × 64 отсчёта, высоты с точностью до 1 мм, нули сжаты, base64. Плитка без правок
не хранится; раскрашенная плитка добавляет до 20 КБ данных до сжатия. Поменяли форму
(`seed`, размеры, шаг) — правки остаются в метрах и переносятся на новую сетку.

## Редактор

* **GameObject → 3D Object → Terrain** — рельеф 512 м с центром в начале координат;
  **Water** — море на нулевой высоте; **GameObject → Snap to Terrain** — поставить
  выделенный объект на землю (меш — нижней гранью).
* Выделите рельеф в 3D-виде Scene — внизу слева панель **Terrain**: Off, Raise, Lower,
  Smooth, Flatten, Paint; Size (м), Strength, Falloff; у Flatten — высота (Ctrl+щелчок по
  рельефу берёт её из-под курсора), у Paint — слой или «Erase paint». Под курсором на
  поверхности рисуется круг кисти (внутренний — где сила полная). Мазок левой кнопкой —
  один шаг Undo. Пока кисть выбрана, левая кнопка не двигает камеру и не выделяет
  объекты (Off — обычный режим); вращение ПКМ и колесо работают.
* Инспектор `Terrain`: раздел **Shape** — черновик параметров формы; **Regenerate**
  применяет его (если есть скульпт — спрашивает: Keep Sculpting / Discard Sculpting /
  Cancel), **Revert** — забыть черновик. **Rendering** (дальность, LOD, тени, море, снег,
  пустыня, масштаб текстур) и **Layers** (текстура и оттенок каждого слоя) — сразу.
  **Sculpting** — сколько плиток изменено, **Clear** — убрать всё.

## Производительность

Замер — тест `perf_terrain` (`cargo test -p engine --test terrain perf_terrain -- --ignored
--nocapture`): земля из примера (2 × 2 км, сид 99, дальность 1600 м, тени, вода, туман),
1280 × 720, камера летит 30 м/с, время кадра — с ожиданием GPU. GTX 1050 Ti, 4 ядра,
dev-профиль; во время замера на машине шли чужие сборки, так что хвосты завышены.

| Что | Значение |
|---|---|
| Кадр в полёте, среднее / медиана | 4.7 мс (214 FPS) / 4.1 мс |
| Кадр, 99-й перцентиль / худший | 15.4 мс / 45 мс |
| Треугольников рельефа в кадре | ≈ 201 000 (384 чанка) |
| Вызовов отрисовки (все проходы) | ≈ 449 |
| Первая загрузка всего видимого (сразу) | 1.7 с на 1002 чанка, 3 потока |
| Построение чанка (поток) | ≈ 4.8 мс (dev, LOD 0 дороже всего) |
| На GPU за кадр в полёте | не больше 16 чанков (в замере — до 9) |
| Память пулов вершин | 19.9 МБ на весь рельеф |

## Пример и тесты

* `cargo run --example terrain_demo` — полёт (ПКМ + мышь, WASD, Q/E, Shift), F — пешком
  персонажем, шары катятся по склону. Снимок без окна:
  `ENGINE_SCREENSHOT=shot.png ENGINE_FRAMES=120 cargo run --example terrain_demo`,
  `TERRAIN_DEMO_VIEW="x,y,z,tx,ty,tz"`, `TERRAIN_DEMO_DESERT=1`.
* `assets/scenes/terrain.scene` — та же земля в редакторе.
* Тесты: `cargo test -p engine --test terrain` (шары лежат на поверхности
  `terrain_height`, луч физики = высота, персонаж всходит на 20° и упирается в 65°,
  скульпт переживает сохранение сцены, подгрузка с бюджетом и выгрузкой, нет щелей между
  LOD по пикселям, раскраска меняет цвет), `cargo test -p engine-render terrain`
  (детерминизм, кисти, кодирование правок, луч).

## Ограничения

* Поворот и масштаб объекта рельефа не учитываются; рельеф — квадрат.
* Разрешение раскраски — сетка высот; вдали (грубые LOD) мелкая раскраска теряется.
* Рассеивания деревьев и камней нет: в образце его тоже нет.
* Коллайдер — полный (ближний LOD) по всему рельефу: 2 × 2 км при шаге 1 м — около 17 МБ
  высот в Rapier.
* Языку Scenario запросы высоты не выданы (только Rust и C++ через сервисы).
