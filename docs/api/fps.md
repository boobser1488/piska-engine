# Контроллер от первого лица (`FpsController`)

Игрок «как в классических шутерах»: разгон и трение на земле, стрейф в воздухе, распрыжка,
присед и прыжок с приседом, ступеньки, скольжение («сёрф») по крутым склонам, подвижные
платформы. Движение считается на фиксированном шаге, камера сглаживается между шагами,
взгляд мышью — каждый кадр. Нужна возможность `physics3d`.

Пример целиком — игра `games/tashbazar` (карта, полоса препятствий, полигон с эталонными
размерами: `TASHBAZAR_SCENE=gym cargo run -p tashbazar`).

## Быстрый старт

```rust
use engine::prelude::*;

fn build() -> Result<App, EngineError> {
    let mut app = engine::app();
    app.world.time.fixed_delta = 1.0 / 64.0;          // классический «тикрейт» (можно и 1/60)
    app.spawn("Floor").at3(0.0, -0.5, 0.0).with(Collider::cuboid(40.0, 1.0, 40.0));
    let player = app.spawn("Player").at3(0.0, 0.0, 0.0).with(FpsController::default()).id();
    // Глаза: ребёнок с камерой. Контроллер сам ставит его на высоту глаз и наклоняет.
    app.spawn("Eyes").child_of(player).with(Camera::perspective(73.74));
    // Захватить курсор (окно игры спрячет и запрёт его; взгляд — по сырому движению мыши).
    app.world.input.set_cursor_captured(true);
    Ok(app)
}
```

В редакторе: объект → **Add Component → Physics 3D → FpsController**, ребёнок с `Camera`
(или назначьте камеру в поле `camera`). Все параметры — поля инспектора.

* Позиция объекта — **у ног** (центр подошвы корпуса). Объект поворачивается только вокруг
  вертикали (yaw), камера-ребёнок — наклоном (pitch) и стоит на высоте глаз.
* Корпусу не нужен `Collider`: контроллер сам протаскивает ящик-корпус через запросы
  физики (`Physics3D::cast_box`). Триггеры корпус не задевает; динамические тела не толкает.
* Подвинуть игрока (респаун, телепорт) — просто записать `transform.position`: контроллер
  заметит это на следующем шаге. Скорость — поле `velocity` (обнулите при респауне).
* Ввод: оси `Horizontal` / `Vertical` (WASD, стик), кнопки `Jump` (пробел; колесо мыши тоже —
  `jump_on_wheel`), `Duck` (если действия нет — LCtrl / C), `Walk` (если нет — LShift),
  `Sprint` (только при `sprint = true`). На паузе ставьте `input_enabled = false`.

## Параметры

Длины — в метрах, классическая единица `engine::fps::UNIT` = 0.01905 м (0.75 дюйма);
`engine::fps::units(250.0)` = 4.7625 м/с, `to_units(м)` — обратно.

| `pitch_limit` | 89° | — | предел наклона взгляда | точно |
| `gamepad_look_speed` | 200°/с | — | правый стик | своё |

Состояние (меняется во время игры, видно в инспекторе): `velocity`, `on_ground`, `ducked`,
`yaw_deg` (0 — взгляд вдоль −Z, плюс — влево), `pitch_deg` (плюс — вверх).
Спидометр: `controller.units_per_second()` — горизонтальная скорость в ед/с;
`horizontal_speed()` — в м/с; `view_direction()` — куда смотрит.

**Угол обзора.** `fov_deg` — горизонтальный угол для экрана 4:3; вертикальный угол
постоянный: `vertical_fov_deg(90) = 2·atan(tan(45°)·3/4) = 73.74°` — его контроллер пишет в
`Camera::fov_deg`. На 16:9 горизонтальный угол шире (Hor+): `horizontal_fov_deg(90, 16/9) =
106.26°`.

## Как устроено движение

Каждый фиксированный шаг (`on_fixed_update`) — одна «команда» `UserCmd` (вперёд/вбок, поворот,
прыжок, присед, шаг) и одна функция `engine::fps::player_move`:

1. **Вытолкнуть**, если корпус оказался в геометрии (`compute_penetration_box`; респаун в стене,
   наехавшая платформа).
2. **Опора**: если стоим на теле, которое сдвинулось или повернулось с прошлого шага (подвижная
   платформа, лифт), игрока переносит вместе с ним (и поворачивает взгляд).
3. **Присед**: на земле глаза опускаются за `duck_time`, корпус становится низким в конце;
   в воздухе — сразу, и ноги подтягиваются на разницу высот корпуса (18 ед), глаза остаются
   на месте: так «прыжок с приседом» достаёт на 18 ед выше (75 вместо 57). Встать можно,
   только если над головой есть место; в воздухе ноги опускаются обратно, если под ними есть место.
4. **Первая половина гравитации** (в воздухе): `v.y −= g·dt/2`.
5. **Прыжок** — только с земли и только по новому нажатию (держать пробел бесполезно, если не
   включён `auto_hop`): `v.y = √(2gh)`. Земля «забывается» сразу, трения в этом шаге нет —
   поэтому прыжок в тот же шаг, что приземлился, не теряет скорость (распрыжка).
6. **Трение** (на земле): `drop = max(speed, stop_speed) · friction · dt`.
7. **Разгон**. Желаемое направление — из поворота и клавиш, желаемая скорость — `max_speed`
   (× присед / шаг). На земле: `accelerate`, прибавка не больше `wish − v·dir`. В воздухе —
   то же, но желаемая скорость срезана до `air_speed_cap` (30 ед/с), а сила разгона считается
   от полной: разгоняться можно только *поперёк* текущей скорости. Отсюда стрейф: повернул мышь
   вправо и держишь D — скорость растёт на ~30 ед/с за шаг (`v' = √(v² + 30²)`), а прямой прыжок
   с W не добавляет ничего.
8. **Перемещение**. На земле: шаг по прямой; упёрлись — «подъём на ступеньку» (вверх на
   `step_size`, вперёд, вниз) против простого скольжения, берётся то, что увело дальше;
   потом прижаться к земле (идём вниз по лестнице, не отрываясь). В воздухе — скольжение:
   до 4 касаний за шаг, после каждого скорость срезается о плоскость касания
   (`clip_velocity`, overbounce 1), в углу — вдоль ребра двух плоскостей, а развернулись против
   исходной скорости — стоп (нет дрожи в углах).
9. **Земля**: короткая трасса вниз (2 ед); земля — если нормаль пологая (`≥ walkable_normal`).
   Быстрее 140 ед/с вверх — точно не земля. Крутой склон — не земля: игрок скользит по нему,
   а стрейф в сторону склона держит его на грани («сёрф»).
10. **Вторая половина гравитации**; на земле `v.y = 0`.

Камера: глаза на высоте `eye_height` (при приседе на земле — плавно); подъём на ступеньку
тело делает за шаг, взгляд — плавно (тест `stairs_lift_the_body_in_steps_but_the_camera_smoothly`).

Трассы корпуса — `Physics3D::cast_box`: ящик против коллайдеров-ящиков считается точно (по
разделяющим осям: сантиметровой погрешности GJK на больших полах нет), против остальных форм —
GJK. Корпус держит зазор 2 мм до поверхностей (`fps::SKIN`): скользя по полу из многих плит или
вдоль стены из многих блоков, он не цепляет рёбра на швах. Протаскивание непрерывное — на
скорости 2000 ед/с сквозь стену в 2 см не проскочить.

**Частота кадров.** Движение — только на фиксированном шаге: одни и те же команды дают один и
тот же путь при 30, 60, 144 и 300 кадрах в секунду (тест `fps_movement`). Камера и тело
рисуются между двумя последними шагами (`Time::fixed_alpha`). Взгляд мышью — каждый кадр, по
смещению мыши за кадр, без сглаживания и ускорения.

**Подвижные платформы.** Тело с `Rigidbody` (Kinematic) и `Collider`, которое скрипт двигает и
поворачивает в `on_fixed_update` (пример — `MovingPlatform` в `games/tashbazar`). Игрок,
стоящий на нём, едет вместе с ним; сверху вниз и снизу вверх не проваливается.

## Захват курсора (`Input`)

```rust
ctx.world.input.set_cursor_captured(true);   // просьба: спрятать и запереть курсор
ctx.input().is_cursor_captured();             // сбылось ли (хозяин игры применил)
ctx.input().cursor_capture_requested();       // последняя просьба игры
```

* Это **просьба**. Окно игры применяет её в конце кадра: `CursorGrabMode::Locked`, где его нет
  (Windows) — `Confined`, курсор прячется; пока курсор захвачен, `mouse_delta()` — сырое
  движение мыши (`DeviceEvent::MouseMotion`: без ускорения ОС, не упирается в край окна), а
  `set_mouse_position` смещение не добавляет. В браузере — Pointer Lock (просите захват по
  клику: браузер разрешает его только после действия пользователя). На Android захвата нет:
  просьба снимается, `is_cursor_captured()` остаётся `false`.
* Потеря фокуса окна, сворачивание, выход из Play / пауза в редакторе зовут
  `Input::release_all()` — она снимает просьбу, хозяин возвращает курсор. Игра видит
  `is_cursor_captured() == false` (удобно ставить паузу) и просит снова, когда игрок вернётся.
* Для хозяина (свой бэкенд, редактор, тесты): сравнить `cursor_capture_requested()` с
  `is_cursor_captured()`, применить разницу и сообщить итог `set_cursor_capture_state(bool)`;
  отказать — просто не ставить `true`.
* `look_requires_capture = true` (по умолчанию): без захвата мышь не крутит взгляд — можно
  кликать по меню.

## Боты и тесты

Команды вместо ввода — через ресурс `FpsRuntime`:

```rust
use engine::fps::{FpsRuntime, UserCmd};
let runtime = app.world.resources.get_or_insert_with(FpsRuntime::default);
runtime.set_command(player, Some(UserCmd { forward: 1.0, yaw_deg: 90.0, ..UserCmd::default() }));
// или команда на каждый шаг: (номер шага, состояние) -> команда
runtime.set_driver(player, |tick, state| UserCmd { jump: state.on_ground, forward: 1.0, ..UserCmd::default() });
let state = app.world.resources.get::<FpsRuntime>().unwrap().state(player).copied(); // MoveState
```

`MoveState`: `origin`, `velocity`, `on_ground`, `ground_normal`, `ground_object`, `ducked`,
`eye_height`, а также события шага `jumped`, `landed` (+ `land_speed`) — для звуков шагов,
прыжка и приземления. Само движение без компонента: `engine::fps::player_move(&settings,
&mut state, &cmd, dt, &PhysicsHullWorld { physics, filter })` — или свой `HullWorld`.

## Запросы формой (`Physics3D`)

| | |
|---|---|
| `cast_box(center, half, motion, filter) -> Option<ShapeHit3D>` | протащить ящик по осям мира |
| `cast_shape(CastShape3D::{Box, Sphere, Capsule}, pos, rot, motion, filter)` | то же для формы |
| `overlap_box(center, half, filter) -> Vec<GameObjectId>` | кто пересекает ящик |
| `compute_penetration_box(center, half, filter) -> Option<Vec3>` | на сколько вытолкнуть |
| `collider_pose(id) -> Option<(Vec3, Quat)>` | поза тела, какой её видят запросы |

`ShapeHit3D { object, fraction, distance, point, normal, started_inside }`: нормаль — у задетой
поверхности, смотрит на форму. Форма, стоящая на поверхности и уходящая от неё (или скользящая
вдоль), не останавливается. `QueryFilter3D::solid()` (без триггеров) / `ignoring(id)` /
`.with_triggers()` / `.with_layers(mask)`.

## Карта под контроллер: размеры

Корпус маленький (1.37 м стоя), поэтому карта для него — «в единицах», а не в человеческих
метрах. Удобные меры (полигон `scenes/gym.scene` показывает их все):

| что | ед | м | почему |
|---|---|---|---|
| ступень лестницы | 8–16 | 0.15–0.30 | ≤ 18 ед заходим шагом; у нас 0.25 м × 0.4–0.45 м |
| порог «уже прыжком» | 19+ | 0.36+ | больше `step_size` |
| ящик «запрыгнуть» | 40–56 | 0.76–1.07 | прыжок 57 ед; ящик карты 0.9 м |
| ящик «только с приседом» | 58–74 | 1.10–1.41 | прыжок с приседом ≈ 75 ед; ящик карты 1.25 м |
| недостижимо | 76+ | 1.45+ | укрытие в рост (≥ 1.8 м — две стопки) |
| лаз (только в приседе) | 55–71 | 1.05–1.35 | корпус в приседе 54 ед, стоя 72 |
| дверь | 112–128 | 2.1–2.4 | 1.6× роста, как в классике; у нас 2.2 × 1.3 м |
| тесный коридор / улица | 128–200 / 320+ | 2.5–3.8 / 6+ | |
| пологий склон / предел | ≤ 45° | | `normal.y ≥ 0.7` — до 45.57° |
| щель «с разбега» | | ≤ 3.4 | полёт 0.75 с × 4.76 м/с = 3.6 м (корпус 0.61 м помогает) |
| щель «нужен стрейф» | | 4.2–4.6 | стрейф за прыжок даёт ~+0.5 м; с распрыжкой — больше |
| высота стен для обзора | | 4–9 | крыши выше 4 м с земли не достать |

Коллайдеры — простые ящики ровно по видимой геометрии (без невидимых «стенок» и выступов):
коплоскостные соседние ящики не мешают скольжению, а выступ даже в 1 см упрёт игрока. Пандус —
повёрнутый ящик (у генератора `games/tashbazar` — `Builder::ramp`); лестница — ящики-ступени:
тело поднимается на ступень за шаг, а камера догоняет его за ~0.1 с (сглаживание ступеней —
подъёмы больше 0.1 м за шаг на земле; склоны и прыжки не сглаживаются).

## Ограничения

* Лестниц-«ладдеров», воды и плавания нет (сознательно пропущены).
* Корпус — ящик по осям мира (как в классике), не поворачивается.
* Динамические тела корпус не толкает, а они не толкают корпус; триггеры его не замечают —
  отметки и зоны проверяйте по позиции (`Checkpoint::contains` в `games/tashbazar`).
* Вид в редакторе: захват курсора выполняет хозяин — вид Game редактора (по фокусу); в
  окне игры — бэкенд окна.
