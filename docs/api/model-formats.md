# Форматы моделей: `.bbmodel`, Minecraft `.json`, `.vox`, `.ply`, `.stl`

Кроме своих `.pmodel` (Piska Modeler), `.obj` и `.gltf` / `.glb` движок и Piska Modeler
читают модели Blockbench, модели блоков / предметов Minecraft, MagicaVoxel и простые
сетки `.ply` / `.stl`. Код чтения — один крейт `crates/engine-model-formats` (без тяжёлых
зависимостей: `serde_json` и `png`); Piska Modeler держит его копию в
`modeler/vendor/engine-model-formats` (`python modeler/scripts/sync_from_engine.py --only
engine-model-formats`).

## Что поддерживается

| Формат | В движке | В Piska Modeler | Берётся | Пропускается (пишется в отчёт) |
|---|---|---|---|---|
| `.bbmodel` (Blockbench 3.x–5.x) | меш + свой атлас | **кубы, группы, меши — правка**; экспорт `.bbmodel` | кубы (`from`/`to`, `origin`, `rotation` X→Y→Z, `inflate`, `rescale`), UV по сторонам (отражения `u2<u1`, поворот 0/90/180/270, `texture: null` — стороны нет), `box_uv` + `uv_offset` + `mirror_uv`, свободные меши, группы `outliner` (вложенные, повороты), текстуры `source` (PNG внутри) или `relative_path`, несколько текстур, `uv_width`/`uv_height`, анимированные текстуры (кадр 0), `export: false`, `model_format: java_block` (сдвиг к центру) | `animations`, `display`, локаторы и прочие типы элементов, цвета, `shade` |
| Minecraft `.json` (блок / предмет) | меш + атлас (`.model.json` или импортёр `Mesh` в `.meta`) | кубы — правка | `elements`, `rotation {origin, axis, angle, rescale}`, стороны (`uv` или UV по положению, `#переменные`, `rotation`), `textures`, `parent` рядом с моделью (`<parent>.json`), анимированные текстуры — кадр 0 | `display`, `overrides`, `gui_light`, `ambientocclusion`, `cullface`, `tintindex`; модель без `elements` (сгенерированные предметы) — ошибка |
| MagicaVoxel `.vox` | жадная сетка + палитра 16×16 | кубоиды (ячейки одного цвета — коробки, закрытые стороны выключены) | `SIZE`/`XYZI`, `RGBA` (без него — палитра по умолчанию), граф `nTRN`/`nGRP`/`nSHP` (перенос, поворот `_r`, скрытые узлы и слои) | `MATL` (стекло, металл), кадры анимации кроме 0 |
| `.ply` (ASCII, двоичный LE и BE) | меш; цвета → палитра-текстура | **меш — правка** (цвета → развёртка) | `vertex` x/y/z, цвета вершин и граней, UV (`s`/`t`, `u`/`v`, `texcoord`), `comment TextureFile` | облака точек (ошибка), прочие элементы |
| `.stl` (ASCII и двоичный) | меш без текстуры | **меш — правка** | треугольники (обход вершин; нормали файла не нужны) | цвета STL |
| `.obj` + `.mtl`, `.gltf` / `.glb` | как раньше | **меш — правка** (UV и текстура из файла; без UV — цвета материалов) | | |
| `.fbx`, `.blend`, `.dae`, `.3ds`, `.max`, `.ma`/`.mb`, `.c4d`, `.skp`, `.usd*` | **нет** — понятная ошибка «FBX is not supported; export the model as glTF (.glb), OBJ, Blockbench (.bbmodel), PLY or STL» | то же | | |

Обычный `.json` в ассетах остаётся файлом данных (импортёр `Text`). Модель Minecraft
импортируется, если файл назван `*.model.json` или в его `.meta` импортёр сменён на `Mesh`.

## Соглашения (проверены тестами)

* Правая тройка, **Y вверх**, «север» — **−Z** (как Blockbench и Minecraft). У `.vox` Z вверх:
  ячейка (x, y, z) → (x, z, −y − 1); модель ставится на землю (наименьший Y = 0) по центру.
  `.ply` / `.stl` по умолчанию считаются Z-вверх (Blender, САПР) — настройка `up_axis`.
* Повороты — градусы, **сначала X, потом Y, потом Z** (`R = Rz·Ry·Rx`, порядок `ZYX` three.js)
  вокруг `origin`; группы — снаружи внутрь (`мир = G_родитель · G · E · v`).
* UV: (0, 0) — левый верхний угол. Сторона куба видна снаружи «стоя»; у верха «север»
  сверху картинки, у низа — «юг». Поворот стороны — картинка по часовой стрелке.
* Обход треугольников — против часовой стрелки снаружи, нормали плоские.
* Единицы: пиксель Blockbench / Minecraft и воксель — 1/16 м (блок = 1 м), `.ply` / `.stl` —
  метр. Множитель — настройка `scale`.

## Настройки импорта (`.meta`)

Новый файл получает их явно; правятся в `.meta`:

```ron
(
    guid: "…",
    importer: "Mesh",
    settings: {
        "filter": Enum("Nearest"),       // атлас пиксельный; Linear — сглаживание
        "scale": Float(1.0),             // множитель к единицам формата
        "up_axis": Enum("Y"),            // "Z" — файл с осью Z вверх (у .ply/.stl по умолчанию)
        "flip_x": Bool(false),           // отразить по X (обход остаётся правильным)
        "bake_groups": Bool(true),       // false — повороты групп (костей) не применяются
        "merge_by_texture": Bool(true),  // false — часть меша на каждую текстуру (свои материалы)
        "double_sided": Bool(false),     // обратные стороны (трава, листья, стекло)
    },
)
```

Все текстуры модели складываются в **один атлас** (столбиком), стороны без текстуры берут
белый блок — рендерер рисует меш-ассет одной встроенной текстурой (как `.pmodel`):
`MeshRenderer` без своей текстуры показывает модель с её картинкой, как в редакторе. Части
по текстурам (`merge_by_texture: false`) остаются диапазонами индексов, чтобы им можно было
назначить разные материалы. Атлас грузится без мипмапов; при `filter: Linear` UV граней
сдвигаются внутрь на полтекселя (без «чужих» цветов на швах).

```rust
use engine::prelude::*;

// Ассет как любой меш: из окна Project перетащить в сцену, или в коде:
let assets = world.resources.get::<AssetDatabase>().unwrap();
let mesh = assets.handle::<Mesh>("models/robot.bbmodel")?;
let png = assets.read_image(mesh.guid())?;          // атлас модели (PNG)
let data = assets.load_mesh(mesh.guid())?;          // MeshData с настройками из .meta
```

Без базы ассетов: `engine_assets::load_mesh("robot.bbmodel")` (настройки по умолчанию,
текстуры — только рядом с моделью) или `engine_assets::load_mesh_bytes_with(имя, байты,
чтение_соседей, &настройки)`. Сам крейт: `engine_assets::model_formats::import(имя, байты,
чтение_соседей, &Options)` → меш, атлас и отчёт (`report.warnings`, `report.ignored`).

## Пределы и безопасность

* Внешние текстуры читаются только по относительным путям внутри каталога ассетов
  (`relative_path`; из абсолютного `path` берётся лишь имя файла рядом с моделью). Пути с
  буквой диска, `/`, `\\`, схемой и выходом выше корня ассетов не открываются.
* Файл до 256 МБ; элементов и групп до 100 000; вложенность групп до 64; текстур до 256,
  сторона текстуры до 8192, атлас до 16 М пикселей; треугольников до 2 000 000; вокселей в
  сцене до 32 М ячеек; координаты по модулю до 10⁶. Счётчики из файла сверяются с его длиной
  до выделения памяти.
* Испорченный файл даёт ошибку с причиной («`from` must be a list of 3 numbers», «the
  binary STL declares 1000000 triangles (50000084 bytes), but the file has 184 bytes»,
  «the .vox scene graph loops»), не панику: это проверяют тесты с обрезанными и
  испорченными образцами.
* Не найденная внешняя текстура — пурпурно-чёрная шахматка и предупреждение в журнале.

## Piska Modeler

File ▸ Open открывает все форматы таблицы новым документом без пути (Save спросит
`.pmodel`; исходник не перезаписывается). `.bbmodel`, Minecraft и `.vox` — кубоидами и
группами, `.obj` / `.glb` / `.gltf` / `.ply` / `.stl` и меши Blockbench — элементами-мешами,
которые выделяются, двигаются, рисуются и правятся по вершинам и граням (подробно —
`docs/api/modeler.md`, раздел «Меши: импорт и правка»). File ▸ Export Blockbench пишет
`.bbmodel` обратно. Для редактора движка: `engine_model_formats::modeler_support(имя)` →
`Native` / `Editable` / `Reference`-совместимо (меши теперь тоже правятся).

## Не сделано

* FBX, Blend, Collada, 3DS — не читаются (см. таблицу; экспортируйте glTF).
* Анимации Blockbench и `display`, материалы MagicaVoxel, цвета STL — пропускаются.
* Скелетная анимация костей Blockbench не переносится: группы «запекаются» в меш.
