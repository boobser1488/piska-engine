# Файл с исходниками проекта (`.pks`)

Один переносимый файл, в котором лежит **исходник проекта**: всё, что нужно, чтобы собрать
проект заново на другом компьютере, и ничего производного. Его пишут и читают Piska Hub
(«Save Project As File…», «Import Project»), редактор (File → Export Project File…) и
`piska-export project-pack | project-unpack | project-info`. Код один — крейт
`crates/engine-project`.

Расширение, названия и описание типа файла берутся из одного места — модуля
`engine_i18n::brand` (см. «Название» в конце). В этом документе `.pks` — расширение сегодня.

## 1. Что входит и что нет

Входит всё, что нужно для сборки: `Cargo.toml`, `Cargo.lock`, `build.rs`, `src/**`, `cpp/**`,
`assets/**` (с файлами `.meta` и `assets/project.settings`), `tests/**`, `tools/**`,
`examples/**`, README, лицензия, значок, `.gitignore`.

Не входит никогда:

| что | почему |
|---|---|
| `target/` (у корня и у вложенных крейтов), `dist/` (если не включён), `.git`, `.hg`, `.svn`, `node_modules`, `__pycache__` | производное |
| `cpp/build/`, `build/` рядом с `CMakeLists.txt`, `CMakeFiles`, `cmake-build-*`, `plugins/*/build`, `plugins/*/bin`, `*.live-*` | папки сборки C++ и «горячие» копии плагинов |
| `.DS_Store`, `Thumbs.db`, `desktop.ini`, `*.tmp`, `*.swp`, `*~`, `.#*`, `*.part` | мусор ОС и временные файлы редакторов |
| `.vscode`, `.idea`, `.vs`, `*.code-workspace` | настройки IDE (можно включить) |
| то, что исключает `.gitignore` проекта | уважаем правила (`/`, `!`, `*`, `?`, `[…]`, `**`; каждый `.gitignore` действует на свой каталог и глубже). `Cargo.toml`, `Cargo.lock` и `project.settings` из архива не исключаются никогда |
| символические ссылки и точки повторной обработки Windows | не выходим за пределы проекта |

Три части включаются параметрами: `tests/` (по умолчанию да), `cpp/` (да), `dist/` — последние
экспортированные сборки (нет). Если `cpp/` выключен, а `build.rs` его собирает, упаковка
сообщает об этом замечанием: распакованный проект не соберётся, пока каталог не вернут.

## 2. Устройство файла (версия формата 1)

```text
заголовок   8 байт  сигнатура 89 50 52 4A 53 0D 0A 1A   (как у PNG: ловит текстовый режим)
            2       версия формата (u16, little-endian)
            2       флаги (0)           4  зарезервировано (0)
запись *    1       0x01
            1       способ: 0 — без сжатия, 1 — deflate
            2       длина имени (u16) + имя в UTF-8, разделитель `/`
            …       блоки данных: [u32 длина > 0][данные] … [u32 0]
            8       размер без сжатия (u64)        4  CRC-32 содержимого
конец       1       0x00
            4       длина списка + список (JSON) + 4 байта CRC-32 списка
трейлер    24       смещение байта 0x00 (u64), длина списка (u32), CRC-32 списка,
                    сигнатура конца 89 50 52 4A 45 0D 0A 1A
```

* Сигнатура **не содержит названия продукта** и не меняется никогда: файлы должны читаться,
  что бы ни случилось с названием.
* Данные каждой записи сжаты отдельно (deflate из `flate2`, уровень 6; уже сжатые форматы —
  png, jpg, ogg, mp3, zip, … — хранятся без сжатия). Повреждение одной записи не прячет
  остальные, а ошибка называет запись.
* Блоки по 32 КБ позволяют писать и читать потоком: на запись нужно знать только имя и
  читать файл по кусочку; на чтение запись можно **пропустить перемоткой**, не распаковывая
  (так хаб читает только `.meta` и `Cargo.toml` в предварительном отчёте).
* Список (манифест) стоит в конце — его пишут одним проходом, после данных — и читается
  первым: из трейлера. Он нужен, чтобы показать содержимое, не читая данных.

### Манифест

```json
{
  "format": 1,
  "project": { "name": "lantern", "title": "Lantern Keeper" },
  "writer": { "tool": "piska-hub", "engine_version": "0.0.1" },
  "created": 1763040000,
  "parts": ["assets", "tests", "cpp", "readme", "icon", "settings"],
  "files": [ { "path": "Cargo.toml", "size": 912, "crc32": 123456789, "packed": 540, "method": 1 } ],
  "totals": { "files": 340, "bytes": 51234567, "packed": 20345678 }
}
```

`parts` — какие необязательные части есть: `assets`, `tests`, `cpp`, `tools`, `examples`,
`builds`, `readme`, `license`, `icon`, `settings`. Неизвестные поля читатель пропускает —
версия 1 может получать новые поля без смены формата; смена формата — это новая версия в
заголовке, и старый читатель отказывается с понятным текстом («обновите движок»).

## 3. Что проверяется при чтении

До записи на диск (`Manifest::validate`):

| проверка | ошибка |
|---|---|
| путь абсолютный (`/…`, `C:…`), содержит `..`, `.`, `\`, `:`, пустой компонент, управляющий символ, имя устройства Windows (`CON`, `NUL`, `COM1`…), заканчивается точкой или пробелом, длиннее 1024 байт | `UnsafePath` — файл не распаковывается |
| два пути, различающиеся только регистром (`A.png` и `a.png`) | `CaseCollision` |
| один и тот же путь дважды; путь одновременно файл и каталог | `Manifest` |
| файлов больше предела (250 000 по умолчанию) | `TooManyFiles` |
| суммарный объём больше предела (64 ГиБ по умолчанию) | `TooLarge` |

Во время чтения:

| проверка | ошибка |
|---|---|
| не наша сигнатура, файл короче заголовка | `NotAProjectFile` |
| версия новее известной | `UnsupportedVersion` |
| нет трейлера, оборван посередине | `Truncated` («скачивание прервано — скачайте заново») |
| не сходится CRC списка, список не читается | `Manifest` |
| заголовок записи не совпадает со списком, данные не распаковываются, размер или CRC записи не сходятся | `Corrupt { entry, … }` — **с именем записи** |
| запись длиннее объявленного в списке (бомба) | `LongerThanDeclared` — чтение останавливается на объявленном размере |
| каталог назначения содержит ссылку на пути, куда пишет распаковка | `LinkInTheWay` |

Файлы пишутся под временным именем `.<имя>.part` и переименовываются; при ошибке и отмене
недописанный файл удаляется.

## 4. Детерминизм

Одинаковый проект и параметры — одинаковые байты: записи по возрастанию пути, времени и
прав внутри записей нет, сжатие детерминировано. Время создания (`created`) записывается
**только по просьбе** (`PackOptions::created`, у `piska-export project-pack` — без
`--reproducible`; хаб и редактор записывают его): воспроизводимый файл удобно сравнивать и
хранить в системе контроля версий. Права доступа (бит «исполняемый») не сохраняются.

## 5. Потоковость и пределы памяти

Файл пишется и читается блоками: проект с ассетами в сотни мегабайт не загружается в
память. Тест `crates/engine-project/tests/streaming.rs` пакует, проверяет и распаковывает
ассет в 200 МБ при пике памяти меньше мегабайта (счётчик аллокатора).

## 6. Командная строка

```text
piska-export project-pack   <каталог проекта> [-o файл.pks] [--no-tests] [--no-cpp] [--builds]
                            [--ide] [--no-gitignore] [--reproducible]
piska-export project-unpack <файл.pks> <каталог> [--conflict fail|skip|overwrite|keep-both]
piska-export project-info   <файл.pks> [--json] [--files] [--verify]
```

`project-pack` по умолчанию пишет `<имя>.pks` в текущий каталог. `project-unpack` по умолчанию
останавливается, если файл уже есть (`fail`); `keep-both` кладёт новый файл рядом как
`имя.imported.расширение` (пара `.meta` идёт за своим ассетом). `project-info` печатает
проект, версию движка, время, части, число файлов и размеры; `--verify` читает всё и сверяет
суммы, `--json` печатает манифест (со списком файлов — с `--files`).

## 7. Piska Hub

* **Save Project As File…** (меню проекта «⋯» и правая кнопка): окно с путём файла, галочками
  «Tests», «C++ sources», «The last exported builds» и подсчётом «сколько войдёт»; запись идёт
  в фоне — полоса задач над строкой состояния показывает файлы и размер, есть **Cancel**, после
  успеха — **Show in Folder**.
* **Import…** на странице Projects: страница **Import Project** (`docs/api/hub.md` §5) — каталог
  проекта, каталог со многими проектами, файл `.pks`; предварительный отчёт, настройки,
  результат. `piska-hub <файл.pks>` и двойной щелчок по файлу открывают страницу с файлом
  (если хаб уже запущен, просьба уходит ему: `hub.request`, строка `import <путь>`);
  файл или каталог можно бросить на окно.

## 8. Редактор

File → **Export Project File…** — то же окно, что в хабе, без выбора каталога (путь
вводится текстом, по умолчанию рядом с проектом). Код — `crates/engine-editor/src/project_file.rs`.

## 9. Крейт `engine-project`

```rust
use engine_project::{pack, unpack, verify, read_info, Control, PackOptions, UnpackOptions, Limits};

let control = Control::new();                         // control.cancel() из другого потока
let summary = pack(project_dir, out_file, &PackOptions::default(), &control, &mut |p| { /* ход */ })?;
let info = read_info(out_file)?;                      // манифест без распаковки
verify(out_file, &Limits::default(), &control, &mut |_| {})?;
unpack(out_file, dest_dir, &UnpackOptions::default(), &control, &mut |_| {})?;
```

Остальное: `collect` (что войдёт), `Conflict` и `merge_tree` (перенос подготовленного дерева в
каталог по политике «skip / overwrite / keep both»), `read_manifest_entries` (прочитать в
память только выбранные маленькие записи), `GitignoreRules`, `validate_relative`.

## Название

Название продукта, расширение файла проекта и каталог настроек живут в
`crates/engine-i18n/src/brand.rs` (`engine_i18n::brand`, из хаба — `engine_editor::kit::i18n::brand`):
`PRODUCT`, `ENGINE_NAME`, `EDITOR_NAME`, `HUB_NAME`, `MODELER_NAME`, `SHORT_NAME`,
`PROJECT_EXTENSION`, `PROJECT_FILE_DESCRIPTION`, `CONFIG_DIR_NAME`. Новый код (формат,
диалоги выбора файлов, справка командной строки, сообщения) берёт их оттуда. При
переименовании движка достаточно поменять константы; старые места, где название ещё
написано в тексте интерфейса (`tr_s("Piska Hub")` и подобное), и имена крейтов, программ и
переменных окружения (`piska-*`, `PISKA_*`, `[package.metadata.piska]`) переименовываются
отдельным заходом.
