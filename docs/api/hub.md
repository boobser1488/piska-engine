# Piska Hub — стартовое окно с проектами

Piska Hub — отдельная программа движка (`tools/piska-hub`), с которой начинается работа:
список проектов, новый проект из шаблона, открытие проекта в редакторе с ходом сборки,
игры-примеры и документация. Как Unity Hub или менеджер проектов Godot.

```bash
cargo run -p piska-hub                      # окно хаба
cargo run -p piska-hub -- --open games/lantern   # сразу открыть проект в редакторе
```

Слева — навигация: **Projects**, **New Project**, **Samples & Docs**, **Settings**; внизу
навигации — что сейчас запущено и где лежит движок. Внизу окна — строка состояния
(последнее сообщение; ошибки остаются, пока по ним не щёлкнут).

Из редактора: **File → Project Hub…** и **File → Open Recent ▸** (см. §7).

---

## 1. Проект — это крейт игры

Хаб работает с крейтами игр, устроенными как `games/template` (`export.md` §1):

| что | зачем |
|---|---|
| `Cargo.toml` с `[package]` и зависимостью `engine` | иначе это не игра на движке |
| `src/lib.rs` с `pub fn build()` | игру собирает библиотека |
| `src/main.rs` (программа игры) | кнопка **Play** |
| `[[bin]] <имя>-editor` с `required-features = ["editor"]` и `src/bin/<имя>-editor.rs` (`engine::editor_main!`) | кнопка **Open** |
| `assets/` | ассеты с `.meta` |

Необязательно, в `[package.metadata.piska]`: `title` (имя в списке), `icon` (картинка из
`assets/` для миниатюры), `dimension = "2d" | "3d"` (метка; без неё хаб угадывает по
компонентам в коде и сценах).

## 2. Список проектов

Откуда берутся проекты:

* все `games/*` рабочего пространства движка, из которого запущен хаб (находятся сами);
* каталоги, добавленные страницей **Import Project** (кнопка **Import…**), и проекты, созданные хабом вне `games/`.

Строка проекта: звезда «закрепить», миниатюра, имя, метки, расположение
(`games/lantern` — относительно движка, или `External` и полный путь), когда открывали,
кнопки **Open**, **Play** (▶) и **⋯**. Метки: `2D` / `3D`, `C++` (каталог `cpp/` или
`build.rs` с `engine-cpp-build`), `Scenario` (есть файлы `.scenario`), `Standalone`
(свой `[workspace]`), `Running` (открыт в редакторе), `No editor` (нет программы
редактора — подсказка у кнопки Open объясняет, что добавить), `Missing`,
`Not a Piska project` (с причиной).

Миниатюра: `icon` из `[package.metadata.piska]` или `assets/icon.png`, для игр-примеров —
кадр из игры, иначе плитка с инициалами и цветом из имени.

* **Поиск** — по имени, заголовку, пакету и пути, слова через пробел (`games 3d`).
* **Sort**: Last opened (по умолчанию) или Name. Закреплённые всегда сверху.
* **Вид**: список или сетка карточек (переключатель справа).
* Щелчок — выделить, двойной щелчок — открыть в редакторе, правая кнопка или **⋯** — меню:

| пункт | что делает |
|---|---|
| Open in Editor | открыть: готовую программу редактора — сразу, иначе собрать (§3) |
| Open Last Build | открыть программу прошлой сборки, не собирая (есть, если проект хоть раз собирался) |
| Rebuild and Open | собрать всегда, затем открыть |
| Rebuild and Play | то же для игры |
| Play | собрать и запустить игру (`cargo build -p <пакет> --bin <пакет>`, затем программа) |
| Export… | окно экспорта: Web / Windows / Android (+ Linux на Linux), Debug / Release; запускает `cargo run -p piska-export -- <платформа> --game <каталог> [--release]` с ходом сборки, после успеха — **Show Output Folder** (`dist/<игра>/<платформа>`). Только для игр из `games/` движка |
| Show in File Manager | открыть каталог в проводнике |
| Pin to Top / Unpin | закрепить вверху |
| Remove from List | убрать из списка. **Файлы не трогаются.** Игра из `games/` запоминается как убранная (вернуть — Settings → Removed engine games → Restore) |
| Delete from Disk… | удалить каталог навсегда — после окна подтверждения с путём. Хаб удаляет только проекты прямо внутри известных ему каталогов (`games/` движка, каталог по умолчанию, каталоги, где он создавал проекты) и не удаляет игры-примеры движка и открытые проекты; иначе объясняет почему |

**Пропавший проект** (каталога больше нет) показан серым с меткой `Missing` и кнопками
**Locate…** (выбрать новое место — закрепление и время открытия переносятся) и
**Remove**.

## 3. Открытие проекта и ход сборки

**Проект без своего кода открывается без компиляции.** Общий редактор `piska-editor`
(`cargo run -p piska-editor -- --project <каталог>`) открывает любой проект: компоненты
движка, Scenario, ассеты и стартовая сцена проекта (`PlayerSettings::default_scene`, иначе
`scenes/main.scene`). Хаб решает сам:

| у проекта | Open | Play |
|---|---|---|
| нет своего кода (новые Empty 2D / Empty 3D) | `piska-editor --project <каталог>` — сразу | `piska-player --project <каталог>` — сразу |
| свой код (`src/scripts/*.rs`, компоненты в `src/`, `cpp/`), программа редактора свежая | программа редактора проекта — сразу | программа игры — сразу (если свежая) |
| свой код, программа не собрана или устарела | общий редактор сразу с `--build`: он сам собирает программу проекта и перезапускается в неё, сцена и правки сохраняются | сборка в фоне, потом запуск |

Компоненты проекта, которых нет в движке, в общем редакторе видны как «missing script» и
сохраняются как были. Первый скрипт на Rust (Assets → New Rust Script…) в общем редакторе
собирает программу редактора проекта и перезапускается в неё (как Build в `editor_main!`).
Сам `piska-editor` (и `piska-player`) хаб собирает один раз, в фоне, если их ещё нет рядом
с хабом или в каталоге сборки; переменные `PISKA_EDITOR` / `PISKA_PLAYER` указывают свои.

**Сборки идут в фоне.** Полоса задач над строкой состояния показывает текущую сборку
(что компилируется, полоса хода, «+2 queued»), **Details** открывает подробное окно (из
него — **Continue in Background**), **Cancel** / **Dismiss**. Пока сборка идёт, хаб работает
как обычно: список, поиск, другие проекты (уже собранные открываются сразу), мастер,
настройки. Новые сборки встают в очередь и идут по одной.

**Open не ждёт сборку, если она не нужна.** Если программа редактора проекта уже собрана
и ни один *собственный* вход проекта (`src/`, `cpp/`, `Cargo.toml`, `build.rs`) не новее
неё, Open запускает её сразу — без cargo. Изменения движка в фоне на это не влияют
(пересобрать с новым движком — ⋯ → Rebuild and Open). Программа ищется там, где её
положила прошлая удачная сборка (хаб это запоминает), иначе в `<каталог сборки>/debug/`
(`CARGO_TARGET_DIR` хаба или `target/` рабочего пространства). То же для **Play**.

В строке проекта под «когда открывали» — состояние: `Built 12 minutes ago`, `Needs build`
(проект менялся после сборки), `Never built`. Состояние перечитывается в фоне, когда окно
хаба снова получает фокус.

**Prebuild All** (кнопка в шапке Projects) собирает по очереди редакторы всех проектов,
которым нужна сборка (свежие пропускаются), ничего не запуская: общий ход «2 of 5»,
затем итог — что собралось, что нет и почему. После этого Open мгновенный.

Если сборка нужна, Open запускает в каталоге проекта

```text
cargo build -p <пакет> --features editor --bin <пакет>-editor --message-format=json
```

и показывает окно хода сборки: что компилируется сейчас, полоса хода (готовые единицы
из сообщений `compiler-artifact` против общего числа из полосы cargo — хаб включает её
переменными `CARGO_TERM_PROGRESS_WHEN=always` / `CARGO_TERM_PROGRESS_WIDTH`; до первого
её сообщения знаменатель берётся из прошлой сборки этого проекта), прошедшее время,
счётчики (собрано, без изменений, предупреждения, ошибки), список ошибок с `файл:строка:столбец`
(щелчок открывает файл программой по умолчанию) и хвост вывода компилятора. Над
выводом — что происходит, простыми словами:

* **Waiting for another build (2:15)** — cargo ждёт, пока другая сборка освободит каталог
  сборки или кэш пакетов; с проектом всё в порядке. Можно ждать, отменить или нажать
  **Open Last Build**.
* **The engine source does not compile right now** — первая ошибка не в проекте, а в
  крейте движка (например, `engine-render`): движок, вероятно, сейчас правят. Показаны
  крейт, `файл:строка` и текст ошибки; **Open Last Build** запускает прошлую сборку.
* **Error in src/player.rs:142:27** — первая ошибка в коде проекта, с текстом.

Кнопка **Open Last Build** (для Play — **Play Last Build**) есть, пока идёт сборка и после
ошибки, если проект уже когда-то собирался: сборка останавливается, запускается прошлая
программа. **Cancel**
останавливает cargo вместе с компиляторами. После ошибки — **Try Again** и **Back to Projects**.

Окружение хаба наследуется: `CARGO_TARGET_DIR`, `RUSTFLAGS`, `ENGINE_*` и прочее — какие
были у хаба, такие получит cargo и редактор.

Когда сборка удалась, хаб запускает программу редактора сам (рабочий каталог — каталог
проекта) и:

* **Hide** (по умолчанию) — прячет окно и возвращается, когда редактор закрыли;
* **Close** (Settings) — закрывает окно; процесс хаба ждёт редактор без окна и выходит
  вместе с ним (хаб, запущенный через `cargo run`, на Windows иначе закрыл бы редактор с собой).

Запущенные программы отслеживаются: проект, открытый в редакторе, второй раз не
открывается (кнопка Open недоступна, в строке `Running`). Закрыть окно хаба, пока
открыт его редактор, можно — окно исчезнет, процесс дождётся редактора.

Первая сборка программы редактора — долгая (в рабочем пространстве движка — минуты:
компилируется игра и редактор; у отдельного проекта — 10–15 минут: движок целиком).

## 4. Новый проект

**New Project**: слева шаблоны с картинками, справа поля.

| шаблон | что внутри |
|---|---|
| Empty 2D | ортографическая камера, земля, квадрат-спрайт (`assets/sprites/square.png`) и компонент `Rotator` в `src/lib.rs` |
| Empty 3D | перспективная камера, солнце с тенями, небо, земля с сеткой, куб с `Rotator` |
| Starfall sample | копия `games/template` («Звездопад») под новым именем: ассеты с теми же `.meta`, код, тесты |

* **Name** — имя пакета Cargo и каталога: строчные латинские буквы, цифры, `_` и `-`,
  начинается с буквы; не ключевое слово Rust (`type` → предложит `type_game`) и не имя
  пакета движка. Под полем — ошибка или будущий каталог.
* **Location** — по умолчанию `games/` движка (Settings меняет), **Browse…** — встроенный
  обзор каталогов. Внутри движка проекты можно создавать только в `games/`.
* **C++ scripts folder** — `build.rs` + `cpp/Wobble.cpp` (пример компонента) и
  `engine::add_static_cpp(&mut app, engine::cpp_scripts!())` в `build()`; нужен
  компилятор C++ (`cpp.md` §17).

Что создаётся (Empty 2D, имя `my_game`):

```text
my_game/
├── Cargo.toml            ← фича editor, [[bin]] my_game-editor, [package.metadata.piska]
├── README.md             ← как запускать и что где
├── assets/
│   ├── scenes/main.scene (+ .meta)
│   └── sprites/square.png (+ .meta)
├── src/
│   ├── lib.rs            ← Rotator, register(), build(), engine::game_main!
│   ├── main.rs           ← программа игры
│   ├── scripts/mod.rs    ← скрипты на Rust из редактора (файл пишет редактор)
│   └── bin/my_game-editor.rs ← engine::editor_main!(my_game::build, …)
└── tests/smoke.rs        ← без окна: сцена загрузилась, Rotator повернул игрока
```

**В `games/` движка** проект становится членом рабочего пространства
(`engine = { path = "../../crates/engine", … }`, `version.workspace = true`) и делит с
движком кэш сборки. **В другом каталоге** проект получает свой `[workspace]`, путь к этой
копии движка, профили как у движка (зависимости оптимизированы), `.gitignore` и копию
`Cargo.lock` движка (те же версии зависимостей). Окно мастера предупреждает: первая
сборка такого проекта компилирует движок — 10–15 минут и несколько ГБ на диске.

**Create and Open** (главная кнопка, Enter) создаёт проект и сразу открывает его; Esc —
назад к списку; поле имени получает фокус, когда страница открывается; мастер помнит
прошлое место и шаблон. Новые Empty 2D / Empty 3D не требуют компиляции: поведение демо —
сценарий `assets/scenarios/spin.scenario` на объекте Player (`ScenarioRunner`), `src/`
готов для кода на Rust. Проект в `games/` после создания ставит в очередь фоновую сборку
своей программы редактора (чтобы первый скрипт потом собирался быстро).

После **Create** — экран готовности: **Open Now**, **Show in File Manager**,
**Back to Projects**. Проект сразу есть в списке.

## 5. Import Project

Кнопка **Import…** в шапке Projects (раньше — «Add Existing…») открывает страницу
**Import Project**; та же страница открывается из командной строки
(`piska-hub <каталог или файл.pks>`), двойным щелчком по файлу проекта (если хаб уже
запущен, просьба уходит ему) и перетаскиванием каталога или файла на окно. Принцип: **пока
не нажато «Import», на диск ничего не пишется**; исходник не меняется никогда.

### 5.1. Источники

Слева — поле пути (Enter добавляет), кнопки **Folder…** и **Project file…** (встроенный
обзор; файлы `.pks` показаны в нём отдельно) и список источников с флажками:

* каталог проекта (`Cargo.toml` + `src/lib.rs`, как у шаблонов хаба; `Cargo.toml` вместо
  каталога тоже годится);
* каталог, в котором проекты лежат глубже: он просматривается в фоне (три уровня, без `target`,
  `dist`, скрытых), найденные проекты добавляются отмеченными — снимите флажки с лишних;
* файл проекта `.pks` (`docs/api/project-file.md`).

Каждый источник сразу разбирается в фоне (папка читается, файл проекта — по списку, без
распаковки), значок справа: ✓ всё хорошо, ⚠ есть замечания, ✕ импорт невозможен.

### 5.2. Предварительный отчёт

Для выбранного источника: имя и заголовок, **версия движка, с которой он сделан** (из списка
файла проекта или `Cargo.lock` — против версии этого движка), состав (сцены, префабы, скрипты
на Rust, файлы C++, скрипты Scenario, размер ассетов), и проблемы по степени тяжести:

| проблема | уровень |
|---|---|
| не проект / нет `src/lib.rs` / нет зависимости от движка; файл проекта повреждён, обрезан, версии новее, с небезопасным путём (`..`, абсолютным), слишком большой | ошибка: импорт невозможен |
| имена, отличающиеся только регистром (Windows, macOS) | ошибка (в Linux — предупреждение) |
| имя проекта уже в списке (копия рядом с оригиналом получает свободное имя `имя_copy`); каталог назначения уже есть и в нём файлы; назначение внутри исходника; назначение внутри движка вне `games/`; недопустимое имя; два проекта импорта с одним именем | предупреждение или ошибка (по смыслу) |
| зависимость-путь на каталог, которого нет на этом компьютере (чужая машина); относительный путь, которого нет рядом; путь зависимости от движка, который не найдётся из нового места при «Keep as is» | предупреждение |
| у ассетов нет `.meta`; один GUID у нескольких файлов | предупреждение |
| версия движка проекта не совпадает с текущей; нужен `rust-version` новее установленного; `rustc` не найден; C++ через CMake, а `cmake` нет в PATH | предупреждение |
| другая редакция Rust; что останется за бортом копии (`target/`, кэши, `.git`, ссылки); есть экспортированные сборки | справка |

Проверки идут по файлам и `Cargo.toml` самого хаба (без запуска `piska-export doctor`:
только `rustc --version` и поиск `cmake` в PATH).

### 5.3. Настройки

У каждой — значение по умолчанию и строка пояснения. Простой случай — два щелчка: источник
и **Import**. Раздел **Advanced** свёрнут.

| настройка | по умолчанию | что делает |
|---|---|---|
| **Name** (для каждого проекта) | имя пакета | имя крейта и каталога; правила как у New Project; живая проверка |
| **How**: Copy into folder / Use in place | Copy | копия в каталог назначения, либо проект только добавляется в список на месте (ничего не копируется и не правится); файл проекта всегда распаковывается |
| **Destination** | прошлый каталог импорта, иначе `games/` движка | внутри `games/` проект входит в рабочее пространство; вне движка получает свой `[workspace]` |
| **After import**: Open in the editor / Build the project's editor in the background / Run the project's tests | нет | действия после импорта; в список проект добавляется всегда |
| **Rename inside** (Advanced) | да | при другом имени: пакет, `[[bin]]`, `lib`, заголовок (если он был выведен из имени), `use old::` в исходниках и тестах, `GAME_NAME`, `-p old`, `old-editor` в README и комментариях, файл `src/bin/old-editor.rs` |
| **Engine dependency** | Use this engine | пути зависимостей на крейты движка (`…/crates/engine*`) указывают на эту копию (`../../crates` в `games/`); Keep as is — не трогать. Вместе с ней `Cargo.toml` **приводится к виду назначения**: член рабочего пространства → отдельный проект (унаследованные `version.workspace = true`, `log.workspace = true` записываются явно, добавляются `[workspace]` и профили), отдельный проект → член (убираются `[workspace]` и `[profile]`); комментарии и остальной текст сохраняются |
| **If files exist** | Keep both | если в каталоге назначения уже есть файлы: Skip (оставить свои), Overwrite (заменить), Keep both (новый — рядом как `имя.imported.расширение`; пара `.meta` идёт за ассетом). Чужие файлы, которых нет в проекте, не трогаются никогда |
| **Asset GUIDs** → Regenerate | нет | новые GUID у всех `.meta` и обновлённые ссылки в сценах, префабах, материалах, настройках (для копии рядом с оригиналом) |
| **Include**: Tests / C++ / Exported builds / IDE settings | да / да / нет / нет | части, которые берутся (для папки — с диска, для файла — из записей) |
| **Line endings** | никогда не преобразуются | файлы копируются байт в байт |

### 5.4. Выполнение и результат

Импорт — фоновая задача (хаб остаётся рабочим; полоса задач показывает ход, **Cancel**,
**Details**). Проект готовится во временном каталоге рядом с назначением
(`.<имя>.importing-<pid>`), правится, проверяется тем же разбором, что и список проектов
(`project::inspect`), и **переименовывается на место**. Отмена и ошибка удаляют временный
каталог — половины проекта не остаётся. Если назначение уже существует, файлы переносятся по
политике «If files exist» (перенос — переименования на одном диске, отмена между файлами).
Хаб не удаляет и не перезаписывает ничего вне выбранного каталога назначения.

Страница результата: по каждому проекту — каталог, число файлов и размер, **Open in Editor**,
**Show in Folder**, список **изменений** (переименования, переписанные пути, преобразование
`Cargo.toml`, новые GUID, оставленные оба файла), список **пропущенного** и **что делать
дальше** (общий редактор открывает проект сразу; свой код — первая сборка; C++ — компилятор;
пути к движку). Ошибки конкретны: у файла проекта — с именем повреждённой записи.

### 5.5. Locate… у пропавшего проекта

Окно **Locate…** осталось: путь с кнопкой «вверх» и списком подкаталогов, проверка
`“Lantern” — 2D, editor program found.` или объяснение, что не так:

| сообщение | что сделать |
|---|---|
| `there is no Cargo.toml in …` | выбрать каталог крейта игры |
| `… is a Cargo workspace, not a game crate` | выбрать каталог игры внутри (`games/<имя>`) |
| `… has no src/lib.rs` | игра — библиотека с `pub fn build()` |
| `… does not depend on the engine` | добавить `engine = { path = "…/crates/engine" }` |
| `Cargo.toml … is not valid TOML` | исправить файл |

## 7. Хаб и редактор

В редакторе, в меню **File**:

* **Project Hub…** — спрашивает про несохранённую сцену (как при выходе), затем
  показывает хаб и закрывает редактор. Если хаб уже работает (он прятался, пока открыт
  редактор), он просто появляется; если нет — редактор запускает его (`piska-hub` рядом со
  своей программой в каталоге сборки, иначе `cargo run -p piska-hub` в рабочем
  пространстве) и, закрыв окно, ждёт его.
* **Open Recent ▸** — недавно открытые в хабе проекты (если хаб уже записывал список).
  Выбор — тот же вопрос про сцену, затем хаб открывает выбранный проект (с ходом
  сборки), а этот редактор закрывается.

Заголовок окна редактора — `Piska Editor: <пакет> — <сцена>`.

## 8. Файлы

Каталог настроек хаба: `%APPDATA%\piska` на Windows, `$XDG_CONFIG_HOME/piska` или
`~/.config/piska` на Linux и macOS; переменная `PISKA_HUB_CONFIG_DIR` его заменяет.

| файл | что |
|---|---|
| `hub.ron` | добавленные проекты, закреплённые, когда открывали, убранные, число единиц прошлой сборки; настройки хаба |
| `recent.txt` | недавние проекты для File → Open Recent: строки `время<TAB>имя<TAB>путь` |
| `hub.alive` | хаб работает: pid и время отметки (обновляется раз в секунду) |
| `hub.request` | просьба редактора: `show` или `open <путь>` (хаб забирает и удаляет) |

```ron
// hub.ron
(
    projects: [
        (path: "C:\\games\\space_miner", favorite: true, last_opened: Some(1763040000), hidden: false, build_units: Some(412)),
    ],
    settings: (default_location: None, after_open: Hide, view: List, sort: LastOpened, project_roots: ["C:\\games"]),
)
```

Испорченный `hub.ron` не мешает запуску: список пуст, в строке состояния — причина, файл
не перезаписывается, пока что-нибудь не поменяется. Масштаб и акцент хранятся в файле
настроек редактора (`editor.md`, Preferences).

Где движок: `PISKA_ENGINE_ROOT`, иначе каталог, из которого собран хаб, иначе вверх от
текущего каталога.

## 9. Из кода и тестов

Хаб — библиотека `piska_hub` плюс маленькая программа. Интерфейс строится
`Hub::ui(&egui::Context)` без GPU, все действия — значения `HubAction`, поэтому хаб
проверяется без окна (`tools/piska-hub/tests/ui.rs` водит мышью по списку, поиску и
мастеру; `tests/shots.rs` снимает экраны в PNG).

```rust
use piska_hub::{Hub, HubAction, HubOptions, Page};

let mut hub = Hub::new(HubOptions {
    config_dir: Some(temp_dir.clone()), // свой hub.ron
    dry_run: true,                      // ничего не запускать: команды — в hub.dry_log
    ..HubOptions::default()
});
hub.apply(HubAction::Open(engine_root.join("games/template")));
assert!(hub.dry_log[0].ends_with("--bin template-editor --message-format=json"));
// вывод cargo в окно хода сборки — строками:
hub.job_mut().unwrap().feed_stderr("   Compiling engine-core v0.0.1");
let png = piska_hub::capture(&mut hub, 1440, 900, 6, |_, _| vec![])?; // снимок без окна
```

| API | что |
|---|---|
| `Hub::new(HubOptions { engine_root, config_dir, dry_run, open })` | хаб; `None` — найти движок и каталог настроек |
| `hub.ui(ctx)` / `hub.update()` | кадр интерфейса / фоновая работа (вывод сборки, процессы, просьбы редактора) |
| `hub.apply(HubAction::…)` | `Open`, `Play`, `Export`, `TogglePin`, `Remove`, `Delete`, `Add`, `Locate`, `CreateProject`, `CancelJob`, `SetView`, `SetSort`, `Navigate(Page)`… |
| `hub.projects()` / `visible_projects()` / `set_search()` | список и поиск |
| `hub.can_delete(path)` | можно ли удалить с диска, или почему нет |
| `HubAction::{OpenLastBuild, PlayLastBuild, RebuildAndOpen, RebuildAndPlay, PrebuildAll, CancelPrebuild}` | открыть без сборки / собрать всегда / собрать все редакторы |
| `hub.last_build(path, &JobKind::Open)` / `hub.job_diagnosis()` / `hub.prebuild()` | программа прошлой сборки; `Diagnosis::{WaitingForLock, EngineBroken, ProjectError}`; ход «Prebuild all» |
| `piska_hub::builds::{inspect_builds, newest_input, state_of, BuildState}` | свежесть программы: `Fresh` / `Stale` / `Never` |
| `job.simulate_exit(ok)` | закончить задание без процесса (тесты в `dry_run`) |
| `Hub::row_id(path)`, `Hub::nav_id(page)`, `Hub::WIZARD_NAME_ID`, `Hub::CREATE_BUTTON_ID`, `hub.search_field_id()` | идентификаторы виджетов для тестов |
| `piska_hub::project::inspect(dir)` | проверить каталог: `ProjectInfo` или `ProjectError` с объяснением |
| `piska_hub::templates::{validate_name, plan, create}` | новый проект без интерфейса |
| `piska_hub::jobs::command_for(info, kind, root)` | команда cargo для Open / Play / Export |
| `piska_hub::cargo::{parse_stdout, parse_stderr, Progress}` | разбор `--message-format=json` и строк состояния cargo |
| `piska_hub::capture(hub, w, h, frames, input)` | хаб в картинку без окна |

Долгие проверки помечены `#[ignore]`:

```bash
# проекты из всех шаблонов проходят cargo check (движок проверяется для отдельного проекта)
cargo test -p piska-hub --test generated -- --ignored every_template_type_checks
# новый пустой проект собирается и проходит свой tests/smoke.rs
cargo test -p piska-hub --test generated -- --ignored an_empty_project_passes_its_smoke_test
# настоящий Open: сборка template-editor, запуск на ENGINE_FRAMES=90 кадров без звука,
# хаб прячется, второй Open того же проекта отклоняется, хаб возвращается
cargo test -p piska-hub --test open_e2e -- --ignored --nocapture
```


### Импорт и сохранение в файл из кода

* `HubOptions { import: vec![путь…], .. }` — открыть страницу импорта с источниками (то же, что
  `piska-hub <путь>`); `HubAction::ImportAdd(путь)`, `ImportScan`, `ImportRemove(i)`, `ImportRun`,
  `ImportCancel`, `ImportReset`, `ShowPack(проект)`, `StartPack(окно)`, `CancelWork(id)`,
  `DismissWork(id)`.
* `hub.import_page()` / `import_page_mut()` — источники (`items[i].report`, `.name`, `.ticked`),
  `settings: import::ImportSettings`, `stage`, `result`; `hub.import_problems(i)` и
  `hub.import_ready()` — проблемы и можно ли запускать; `hub.works()` — фоновые задачи
  (`tasks::Work`: `state`, `progress`, `cancel()`); `wait_for_import()` / `wait_for_works()` — дождаться
  (тесты). В `dry_run` разбор и поиск идут сразу, задачи — в потоках.
* Логика без окна — `piska_hub::import`: `analyze`, `check_plan`, `run_item`, `rewrite_manifest`,
  `regenerate_guids`, `scan_for_projects`.

## 10. Ограничения

* Хаб не открывает окно существующего редактора поверх других: если проект уже открыт,
  кнопка Open недоступна, переключиться на окно редактора нужно самому.
* Миниатюра «последний кадр редактора» не делается: редактор снимков для хаба не пишет.
  Есть значок из ассетов, кадры примеров и плитка из имени.
* Ход сборки с `CARGO_TERM_PROGRESS_*` зависит от того, печатает ли cargo полосу в канал;
  если нет — знаменатель берётся из прошлой сборки проекта, при первой сборке полоса
  неопределённая (бегущий отрезок), а счётчики и текущий крейт идут как обычно.
* Ошибка с `файл:строка` открывает файл программой по умолчанию — без перехода к строке.
* Экспорт из хаба — только для игр из `games/` движка (так устроен `piska-export`).
* Экспорт проекта без своего кода общим проигрывателем без компиляции не сделан. Что для
  этого нужно: `piska-export` положил бы готовый `piska-player` (собранный в release один
  раз) рядом с паком ассетов проекта и научил бы проигрыватель брать проект из пака рядом
  с собой (`engine::assets::install_pack` до старта); для веба и Android — заранее собранные
  wasm / APK-оболочки с тем же проигрывателем.
